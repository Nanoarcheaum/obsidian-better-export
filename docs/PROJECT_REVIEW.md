# 项目评价 · 0.8.1

评价基于源代码、配置、39 项逻辑测试、18 项浏览器测试及 PDF 内容核对；模拟宿主测试不等于真实 Obsidian 验收。

## 总体判断

适合发布公开测试版，尚不足以承诺稳定生产使用。论文与报告场景明确，已形成从排版、模板、引用到预览输出的完整流程。主要瓶颈是宿主兼容性、复杂状态管理与维护成本，而不是功能数量。

## 优点

1. 场景完整：全局配置与局部设置协作，图片封面、公式和引用有实际写作用途。
2. 保护输出正确性：等待资源、作废旧渲染、预览错误时禁止打印，减少静默截断。
3. 有回归证据：测试覆盖长段落、表格、引用更新、异步关闭、模板隔离和粘贴。一个 9 页 A4 样本核对 18,004 个非空白字符，未丢失或重复；这不是对所有文档的保证。
4. 引用使用成熟 CSL 引擎，资源内置并保留来源哈希；开启严格类型检查，依赖有锁文件。

## 主要不足

| 方面 | 观察 | 影响与优先级 |
| --- | --- | --- |
| 真实应用验证 | 浏览器使用简化 Markdown/MathJax 适配器，未验证真实 Vault | 最高优先级：验证公式、嵌入、主题、打印和最低支持版本 |
| 代码结构 | main.ts 约 2,800 行，面板、模板、导入、持久化与渲染控制集中 | 拆分控制器、设置存储、家具渲染及引用界面 |
| Markdown 语法 | 部分转换用正则保护上下文，并非完整语法树 | 增加嵌套围栏、HTML、转义和多行公式语料，逐步统一解析 |
| 分页性能 | 依赖 DOM 试排和节点复制；长表格有多轮扫描 | 现有样本不能证明百页文档性能，需要长度/时间/内存基准 |
| 数据维护 | 存在多个按路径存储的映射与模板快照 | 补充设置版本迁移、坏数据恢复与长期清理 |
| 用户体验 | 模板和文献数量增加时面板较长 | 全局模板已独立；下一步需要搜索、示例和键盘可用性检查 |
| 发行成熟度 | 尚无社区市场审核和多平台用户反馈 | 标注测试版，避免把测试通过表述为普遍兼容 |

## 本次发布整理

- 全局模板从 2×2 页签改为独立可展开面板，三个局部分页恢复单行。
- 统一名称 Better Export 与作者 Nanoarcheaum，保留插件 ID。
- 修复 README 公式示例损坏，补齐安装、更新、许可和贡献资料。
- 修正版本映射，添加 Windows/Ubuntu CI、问题模板和源码发行包。

## 下一阶段

1. 在隔离真实 Vault 完成公式、封面、引用、长表格、打印与至少两种主题验收。
2. 验证 Windows/macOS/Linux 和最低支持版本，按结果调整声明。
3. 拆分 main.ts，增加配置迁移和坏数据恢复。
4. 用 10/50/100 页文档建立性能和分页一致性基准。

在这些工作完成前，不建议大量扩充导出格式。现有功能的稳定性更能决定项目价值。
